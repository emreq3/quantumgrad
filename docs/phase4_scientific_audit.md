# Phase 4 scientific audit

Scope: every scientific claim used in a mission or dashboard was re-checked against the engine's actual outputs, the committed benchmark data, analytical references and the research
documents. Passing unit tests were not taken as proof that an *interpretation* is right: for each item below the source code path, the numbers and the wording shown to the player were
reviewed. Corrections from earlier phases (`research_corrections.md` C1–C10) were re-read against the code that implements them; none had to be reverted.

## 1. Result integrity (nothing physical changed)

All standard benchmarks (detection, mitigation, correction, fixed-round correction, optimization) were regenerated from a **clean committed revision** (`ca36e31`) and the campaign was re-exported
(`dddb734`). `python scripts/compare_results.py` compares them with the previously committed files: **140 035 numeric/text values compared, 0 differences** (wall-clock, revision and machine fields are
ignored). The only intended differences in the exported campaign are conditions/success flags of D1 and D4 (bug B-02), the M3 credit budget (B-01), new `units`, model labels, stabilizer types and
lattice positions (presentation data), and the C6 score no longer including wall-clock time (B-11). Modified scientific modules: `correction/surface.py` (adds `type` to `geometry()`),
`correction/manual.py` (adds `code_capacity_edge_qubits`), `optimization/pareto.py` (adds `relative_regret`), `scenarios/build.py` (conditions, units, labels, gate), `bench.py` (new fixed-round benchmark),
`game/*` (solvability, save v2). No simulation, noise model, decoder or estimator was modified.

## 3. Exploit review (scoring, accounting, leakage)

| Vector | Result |
|---|---|
| Repeated execution | Every executed action charges its exported units; a second N1 execution of the most shot-hungry winner exceeds the 16 000-shot cap and is refused (`test_second_execution_cannot_exceed_the_shot_budget`). |
| Double click / key repeat | Re-entrancy-safe store: second call in the same tick is refused, charged once. |
| Negative / unpriced resources | `creditCost` and `credit_cost` throw for negative or unpriced keys; `Ledger` rejects negative balances and double refunds. |
| Invalid allocation keys | Refused with a notice, nothing charged; no fallback outcome is ever substituted. |
| Stale state | Mission, wallet and state are mirrored synchronously; leaving a mission clears attempt state; tests drive navigation during execution. |
| Hidden answers in the ordinary UI | The injected fault (D3), the true logical flip and MWPM edges (C-missions), Pareto status, dominating candidates and N1 reference baselines are not rendered before they are earned (4 tests). **Not claimed**: the static `campaign.json` contains them and anyone can read it; only the API's session mode gates them. |

## 4. Remaining scientific limitations

Synthetic noise only; detection exactness limited to ≤ 10 simulated qubits; no PEC / PNA / SLC / NoiseLearnerV3 / DD / Pauli twirling; MWPM only; no correlated or leakage noise; fixed-round and distance-scaled correction experiments are both circuit-level
depolarizing with one decoder, so they say nothing about real devices; the 60 000–200 000-trial samples cannot resolve d = 7 failure rates below ~10⁻⁵; threshold estimation was deliberately not attempted; hardware was not used (see `hardware_readiness.md`).
