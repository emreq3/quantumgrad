# Known limitations

Honest list of what QTA6 does **not** do or does only partially (updated for Phase 4).

## Scientific scope
* **Synthetic noise only.** No profile is a measured device calibration. Correlated, leakage, crosstalk, burst and non-Markovian noise are not implemented; drift is a simple parameter scaling.
* **Detection:** exact evaluation limited to ≤ 10 data+ancilla qubits in tests and ≤ 6 data qubits in the live API; Clifford payloads are random brickwork states, not application circuits; only Paulice's stabilizer mode with `cost="gamma"`/windowed placement is used; single-fault classification is first-order. Reported fidelities are conditional on acceptance (always shown with it).
* **Mitigation:** Pauli twirling, dynamical decoupling, PEC, PNA, SLC and NoiseLearnerV3 are **not implemented**. Readout calibration is simplified (full/tensor). ZNE uses global unitary folding with exact noisy simulation as the "device". Mitigation MSE is an average over 300 repeated trials, not the error of the single run on screen.
* **Correction:** only MWPM (PyMatching); no union-find, tensor-network, correlated matching, leakage, lattice surgery or logical gates. The manual decoder uses the code-capacity (C2–C5, C8) and phenomenological (C7) models, **not** the circuit-level model (C6 and the benchmarks). Two benchmarks (rounds = d and rounds = 3) show that the apparent crossover moves with the round policy; **no threshold is claimed**, and d = 7 at p = 0.001 rests on 1 observed failure.
* **Optimization:** "optimal" means optimal inside the enumerated action space.
* **Hardware:** nothing was run on quantum hardware (see `hardware_readiness.md`).

## Game
* All campaign outcomes are **precomputed** and replayed; only the sandbox (needs the API) is live. Results are generated by validated quantum simulations, never invented, but they are not computed in the browser.
* **Reference answers are not secret** in the static bundle (`campaign.json` is public); the ordinary interface does not render them before they are earned (tested), and the API's session mode gates them.
* Difficulty, scoring weights and economy values are design choices; **no human playtest has been performed** — the campaign was completed by automated drivers (engine and real browser), which is not a user study.
* Characters, setting and events are fiction; dialogue is English text only (no voice, no localization).

## Presentation, audio and accessibility
* Artwork is original **procedural vector art** (no hand-painted illustration, no character animation); the city map is a stylized schematic. Phase 4 art direction is implemented, but not "final production art".
* Audio is synthesised placeholder-grade sound design; it was verified to execute in a real browser (context running, clock advancing, mute honoured) but **has not been listened to by a person**.
* Accessibility: axe-core reports 0 violations on 32 screen scans, 11 scripted keyboard checks pass, layout is overflow-free on four viewports — **this is not formal WCAG conformance**; no screen-reader, switch, voice-control or physical-device testing was done (`accessibility_audit.md` §5).

## Engineering and deployment
* **GitHub Pages is not deployed**: the repository needs a one-time admin setting (see `deployment.md`); the build was verified under a sub-path only.
* Chromium only (Playwright); Firefox/Safari untested. No service worker (not an installable PWA). Unused `.woff` font fallbacks (142 kB) ship in `dist/`.
* Python 3.12 only; Windows/macOS untested. The extended benchmark profile was not run. No load testing of the API.
* The license of the project is **not chosen yet** (`asset_manifest.md`).
